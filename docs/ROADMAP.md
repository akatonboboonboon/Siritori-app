# 開発ロードマップ

このロードマップは、独自機能を安全に追加しながら、リポジトリ所有者本人が
説明できる実装を残すための共同開発計画です。大きな機能を1つのPRへまとめず、
各段階を独立してレビュー、テスト、公開できる状態にします。

## 現在の実装状況

安全性・同時実行基盤と主要画面はmainへ統合済みです。

- Sudachi辞書、自由初手、複数読み選択、表記＋読み履歴、時間制限の状態機械
- Argon2id、不透明セッション、CSRF／Origin検証、正規化ユーザー名＋IPの有界な回数制限
- Neon PostgreSQLを正本にするスキーマ、Alembic、ロビー・部屋・対局のSQLリポジトリ
- 部屋コード、定員、準備、所有者移譲、開始済み対局検索、プレイヤー・観戦者権限
- 部屋単位ロック、状態バージョン、操作ID＋意味的フィンガープリントによる安全な再送
- 切断・プロセス再起動後の不在猶予、Bot引継ぎ、安全な手番境界での本人復帰
- 空PvP部屋削除、厳密な`Game`スナップショットによるソロ戦の保存・一時停止・再開
- サーバー側テーマ制約、Easy／Normal／Hard Bot、Render + Neon設定、GitHub Actions
- 公開ゲーム、認証、ソロBot戦、オンライン対戦画面のPC・スマートフォン対応

最終統合後の全298件の自動テストが成功しています。
Render Blueprintは準備済みです。Dashboardの秘密情報と公開URLはリポジトリ所有者が確認し、
秘密情報は受領・記録しません。

固定開始単語は廃止済みです。ランダムに選ばれた先攻が、辞書にある好きな単語を
最初に入力します。

本人担当として残しているのは、部屋・対戦の最終UI、テーマ分類データの目視確認、
タイマーの見た目、実端末確認、公開操作、本人の説明文です。

## 開発原則

1. ゲーム規則は [`RULES.md`](./RULES.md) を正本にする
2. 画面ではなくサーバーが、単語、手番、期限、権限を判定する
3. 生成AIを実在語判定に使用しない
4. ドメインルールをNiceGUIの画面コードから分離する
5. 認証情報と進行中の試合をプロセスメモリだけに置かない
6. 各PRを、人間が読める大きさと1つの目的に限定する
7. 新しい画面は、PCとスマートフォンの両方の合格条件を満たしてから完了とする

## Phase 0: 仕様固定

**成果物**

- 単語、勝敗、時間、切断、Botの規則
- 段階的な実装順
- AIとユーザーの担当境界

**完了条件**

- 実装者が判断を補わなくても、正常系と主要な境界系のテストを書ける
- ルール変更は文書変更から始めることが合意されている

この段階では新しい画面を作りません。

## Phase 1: 実在語判定と自由な初手

**現状:** AI担当の辞書、状態機械、公開画面、読み選択、履歴は実装済みです。

**実装範囲**

- 差し替え可能な `Lexicon` インターフェース
- バージョンを固定した日本語辞書
- 入力表記、読み、辞書ID、テーマの分離
- 漢字・カタカナからひらがなの読みへの変換
- 曖昧な読みの選択
- 未知語、絵文字、不正形式、直接入力したひらがな・カタカナ1文字の拒否
- 正規化した読みによる接続と重複判定
- 固定開始単語の廃止
- サーバー側でのランダムな先攻決定
- 入力表記と読みを含む履歴

**受け入れテスト**

- `あ` と `カ` を拒否し、辞書に登録された `蚊` を読み `か` として受理する
- 絵文字、空白だけ、未知のひらがな列、未知の漢字列を拒否する
- `林檎` を `りんご` として受理し、その後の `りんご` を重複と判定する
- 読みが複数ある単語を勝手に確定しない
- 初手には接続条件を課さず、2手目から通常の接続を行う
- 不正入力と読み選択中は手番を進めない

**新規・変更画面のレスポンシブ合格条件**

ゲーム画面:

- PC（1280×720以上）では、現在単語・入力操作・履歴を同時に確認でき、
  主要入力領域が横に過度に広がらない
- スマートフォン（幅320px以上）では1列に並び、横スクロールが発生しない
- スマートフォンのソフトウェアキーボード表示中も、入力欄、送信ボタン、
  エラーメッセージのいずれも操作・確認できる
- タッチ対象は44×44px以上とし、送信とリセットを誤タップしにくく離す
- 入力表記と読みは、長い単語でもカード外へはみ出さず折り返す

読み選択ダイアログ:

- PCでは候補一覧、読み、補足情報、確定・取消操作が1つのダイアログ内に収まる
- スマートフォンでは画面幅から左右16px以上の余白を確保し、候補が多い場合は
  ダイアログ内部だけを縦スクロールできる
- キーボードだけでも候補選択と取消ができ、フォーカスが背後の画面へ抜けない

## Phase 2: テーマと時間制限

**現状:** サーバー側のテーマ照合、期限、時間切れ処理は実装済みです。分類データ、
設定UI、タイマー警告表示は本人担当です。

**実装範囲**

- 「指定なし」と、根拠を確認した複数テーマ
- テーマ別の辞書索引
- 無制限または3～180秒の1手ごとの制限
- サーバー管理の期限
- 時間切れと合法候補なしの勝敗処理

**受け入れテスト**

- 選択テーマ外の実在語を拒否する
- 不正入力では期限を延長しない
- 有効な単語の確定後にだけ次の期限を開始する
- クライアントの時計を変更しても結果へ影響しない
- 時間切れを同時に処理しても勝敗を1回だけ保存する

**新規・変更画面のレスポンシブ合格条件**

ゲーム設定画面:

- PCではテーマと時間設定をグループ化し、選択内容と「開始」を同時に確認できる
- スマートフォンでは設定項目を1列にし、幅320pxでもラベルを省略しない
- 時間スライダーを採用する場合、値を数字でも確認でき、タッチ操作だけで
  無制限・3秒・180秒を正確に選べる
- テーマが増えても横スクロールさせず、折り返しまたは縦一覧で表示する

タイマー付きゲーム画面:

- PCとスマートフォンの両方で、現在の手番と残り時間をスクロールせず確認できる
- 残り時間を色だけで伝えず、数字とテキストでも警告する
- 幅320pxでもタイマーが入力欄を押し出さない

## Phase 3: ログインと永続化

**現状:** 強化済み認証、保護画面、SQL永続化、AlembicはAI担当として実装済みです。
本人が最終画面と再起動後の手動確認を行います。

**実装範囲**

- ユーザー登録、ログイン、ログアウト
- 安全なパスワードハッシュとセッション
- PostgreSQLのスキーマとマイグレーション
- ユーザー、試合、手番、履歴、保存中ゲームの永続化
- 環境変数による秘密情報管理

**受け入れテスト**

- ユーザー名を重複登録できない
- 平文パスワードをDBとログへ残さない
- 誤ったログインでは、どちらの項目が誤りかを漏らさない
- ログアウト後は保護された画面へ入れない
- アプリ再起動後もユーザーと保存済み試合を復元できる

**新規画面のレスポンシブ合格条件**

登録画面・ログイン画面:

- PCではフォーム幅を読みやすい範囲に制限し、空いた画面全体へ引き伸ばさない
- スマートフォンでは幅320pxで左右16px以上の余白を保ち、横スクロールしない
- ソフトウェアキーボード表示中も、現在の入力欄、エラー、送信ボタンへ移動できる
- パスワード表示切替は44×44px以上のタッチ領域と説明可能なラベルを持つ
- バリデーションエラーでレイアウトが重なったり、入力済みユーザー名が消えたりしない

保存済みゲーム一覧:

- PCでは状態、相手、更新日時、再開操作を同じ行またはカードで比較できる
- スマートフォンでは各ゲームを1列カードにし、主要情報と再開操作を省略しない
- 0件、読み込み中、取得失敗の状態を、それぞれ専用の表示で区別する

## Phase 4: 部屋、対戦、観戦

**現状:** ロビー、部屋、権限、同期、競合制御とNiceGUI画面は実装済みです。
本人は公開URLと実機で、観戦・切断・復帰と最終デザインを確認します。

**実装範囲**

- 部屋作成と招待コード
- 2人対戦のロビーと準備状態
- プレイヤーと観戦者の権限
- サーバーを正とする手番、履歴、タイマーのリアルタイム同期
- 部屋単位の排他制御
- 再読み込みと一時切断からの復帰

**受け入れテスト**

- 手番でないユーザーと観戦者の送信を拒否する
- 同時に2件を送っても1件だけ受理する
- プレイヤーと観戦者で同じ履歴順を表示する
- 再読み込み後も部屋、役割、手番、期限を復元する
- 招待コードから別の部屋へ入れない

**新規画面のレスポンシブ合格条件**

部屋作成・参加画面:

- PCでは作成と招待コード参加を視覚的に分け、誤操作しない
- スマートフォンでは両操作を1列にし、招待コードを入力しても送信ボタンが隠れない
- 部屋コードのコピー・貼り付け操作をタッチとキーボードの両方で行える

ロビー画面:

- PCでは参加者、役割、準備状態、部屋設定、開始操作を同時に確認できる
- スマートフォンでは参加者一覧が長くなっても開始・退出操作へ到達でき、
  固定要素同士が重ならない
- 幅320pxでも長いユーザー名を省略表示しつつ、完全な名前を確認する方法を提供する

対戦画面:

- PCでは盤面、履歴、参加者、タイマーを整理して表示し、入力操作を常に識別できる
- スマートフォンでは現在単語、手番、タイマー、入力を上位に置き、
  履歴と参加者はその下または開閉領域へ置く
- 幅320pxで横スクロールせず、履歴の長い表記と読みを折り返す
- 接続状態が変わっても入力欄や送信ボタンが不意に移動しない

観戦画面:

- PCとスマートフォンの両方で「観戦中」を常時判別できる
- 単語入力操作を表示しないか、無効である理由を明示する
- スマートフォンでも現在単語、手番、タイマーをスクロールせず確認できる

## Phase 5: 1人用Bot戦

**現状:** Easy／Normal／Hard、Bot数、一般語30,547語の索引、設定・対局画面、
厳密な`Game`スナップショットでの保存・一時停止・再開は実装済みです。
タイマー警告は実装済みで、最終的な表示確認は本人担当です。

**実装範囲**

- Easy、Normal、Hardの戦略
- Bot数の変更
- 合法候補の高速索引
- Bot戦の保存、一時停止、再開
- 再現可能な乱数

**受け入れテスト**

- すべてのBot出力が辞書、テーマ、接続、未使用条件を満たす
- Easyは固定シードで再現できる
- Normalは候補がある限り末尾「ん」を避ける
- Hardはテスト用辞書で相手候補を減らす手を選ぶ
- 最短の3秒設定で期限内に応答する
- 保存・再開後に履歴、手番、使用済み語を失わない

**新規画面のレスポンシブ合格条件**

Bot戦設定画面:

- PCでは難易度、Bot数、テーマ、時間、開始操作の関係を一覧できる
- スマートフォンでは設定を1列にし、幅320pxでも増減ボタンと現在値を同時に確認できる
- 難易度を色だけで区別せず、名前と説明を表示する
- 選択したBot数に応じて説明が増えても、開始ボタンと重ならない

一時停止中Bot戦・再開画面:

- PCでは保存時点、進行状況、設定、再開・削除を比較できる
- スマートフォンでは危険な削除操作を再開操作から離し、確認なしに実行しない
- オフラインや再開失敗時に、保存データを消さず再試行できる表示を出す

## Phase 6: 切断時のBot引き継ぎと部屋寿命

**現状:** 複数タブpresence、15秒猶予、再起動後の不在処理、Bot引継ぎ・本人復帰、
空部屋処理は実装済みです。状態表示と実ブラウザでの切断試験は本人担当です。

**実装範囲**

- 明示退出と通信断の区別
- 15秒の再接続猶予
- Botへの席の引き継ぎ
- 本人復帰時の安全な席の返却
- 人間が0人になった対人部屋の即時削除
- 人間が0人になったBot戦の保存と一時停止

**受け入れテスト**

- 猶予内の復帰ではBotが手を送らない
- 猶予後はBotが同じ状態から引き継ぐ
- 本人復帰とBot送信が競合しても1手だけを受理する
- 最後の人間が消えた対人部屋を削除する
- 最後の人間が消えたBot戦を削除せず、一時停止として保存する

**新規・変更画面のレスポンシブ合格条件**

切断・再接続表示:

- PCとスマートフォンの両方で、切断中、猶予残り時間、Bot引き継ぎ済み、
  本人復帰済みを別の状態として表示する
- スマートフォンでは状態バナーが現在単語、タイマー、入力欄を覆わない
- 色だけで状態を区別せず、短い文章とアイコンを併用する
- 再接続中に連打可能な送信操作を残さない

部屋削除・Bot戦一時停止結果画面:

- PCとスマートフォンの両方で、削除された対人部屋と保存されたBot戦を明確に区別する
- 幅320pxでも、部屋一覧へ戻る操作とBot戦を再開する操作を誤認しない

## AIとユーザーの担当

### ユーザーが担当するコード

提出時に自分の設計意図を説明できるよう、次をユーザー主体で実装します。

- `RULES.md` の最終判断と、ルール変更の提案
- ロビー、部屋カード、履歴行、テーマ選択、タイマー設定のUI
- テーマ分類データの選定、追加、誤分類の修正
- Easy／Normal／Hardの強さと収録語のプレイ感レビュー
- タイマーの見た目と警告表示
- 自分が追加した機能の正常系・異常系テスト
- PC・スマートフォンでの手動確認
- READMEの工夫した点、学んだこと、AIを使わず実装した範囲

ユーザーの変更は `user/...` ブランチから小さなPRにし、AI側も同じリポジトリから
取得してレビュー・統合します。

### AIが担当するコード

安全性や同時実行制御が重要な基盤はAIが下書きし、変更理由を説明します。

- 辞書を差し替えられる単語判定基盤
- ゲーム状態機械の分離
- DBスキーマとマイグレーション
- パスワードハッシュ、セッション、権限チェック
- 部屋単位の排他制御
- 切断、Bot引き継ぎ、本人復帰の競合対策
- GitHub Actions、Render設定、自動テストの土台

### 共同で担当すること

- 辞書の収録範囲、ライセンス、出典の確認
- PRの相互レビュー
- 境界ケースと受け入れテストの追加
- 2ブラウザ以上を使った対戦、観戦、切断試験
- AIが作成したコードを、ユーザーが説明できる状態にする

AIが作成したコードと、ユーザーが変更・作成したコードは `AI_USAGE.md` とPR本文に
記録します。ユーザー担当部分をAIが先回りして完成させないことも、この共同開発の
完了条件に含めます。

## PRの推奨順

1. `docs: define word and game rules`
2. `feat: add lexicon-backed word validation`
3. `feat: add first-turn selection and reading choice`
4. `feat: add themes and server-side timer`
5. `feat: add authentication and persistence`
6. `feat: add rooms and spectator mode`
7. `feat: add solo bot matches`
8. `feat: add disconnect takeover and room cleanup`
9. `chore: deploy and verify on Render`

各PRは、対象機能の自動テスト、対象画面のPC・スマートフォン確認結果、
AIとユーザーの担当範囲を本文へ記載してからレビューします。
